# Performance evaluation (Member 3)

All numbers are generated by `python -m benchmark.run_benchmark` and written to `results/`. Each scenario is replicated over independent random seeds; every seed produces a fresh Member 1 trace and fresh background jobs, and all six schedulers run on exactly the same task set (paired design). Values are means with 95% t-intervals.

## Discussion

1. **Chat quality.** In the heavy scenario TLS leaves 27% of requests violating their SLA, against 95% for Round Robin, 95% for the CFS-like scheduler, 64% for static priority, 69% for FCFS and 68% for EDF. Pooled over all scenarios the improvement is significant against every baseline after Holm correction.
2. **Where TLS does not win.** FCFS has a lower raw token-late rate (1.8% vs 2.9%) and lower p99 gap, because it never interleaves requests: tokens flow smoothly once a request starts, but requests wait in a queue for their first token. The token-level rate counts that wait as a single miss. This is why we also report the request-level SLA rate.
3. **Cost.** TLS makes background jobs 7.1x slower in the heavy scenario (static priority 1.5x, Round Robin 2.4x). That is the price of protecting streams; it is not hidden by the headline metric.
4. **Fairness and throughput.** TLS has the highest Jain index in every loaded scenario (0.984 heavy). Throughput matches EDF and is about 28% above Round Robin in the heavy scenario, because RR and CFS waste work on late tokens and context switches.
5. **Design ablation.** The capacity planner is the component that matters. Mid-token preemption showed no measurable effect in these workloads, and the starvation guard trades a small inference penalty for background fairness.

## Threats to validity

- Everything is simulated. CPU time is modelled; memory-bandwidth and cache contention are not.
- Member 1's traces are synthetic and scaled by Member 2's headroom constant (0.7 of the SLA target); results depend on that calibration.
- The CFS-like baseline is a simplified vruntime model, not the Linux kernel scheduler.
- Scenario parameters were chosen to span load levels, not tuned to favour any scheduler; TLS parameters are Member 2's defaults.
